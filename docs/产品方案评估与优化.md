# 时薪时钟 SalaryClock · 产品方案评估与优化

> 版本 v0.1 · 2026-10-31
> 一句话定义：**把月薪换算成"此刻每秒在赚多少钱"，并在「打卡 / 加班 / 下班」三个节点给出可感知的反馈。**

---

## 0. 结论先行

| 判断 | 结论 |
| --- | --- |
| 需求是否成立 | ✅ 成立。它解决的不是"算工资"，而是"上班时间的价值感"——这是情绪需求，不是工具刚需，所以必须够轻、够快、够好看 |
| 技术难度 | ✅ 很低。纯前端 + 本地存储即可跑通全部核心流程，无需后端 |

| 建议的 MVP 边界 | 单份工作、两档费率（正常/加班）、定位围栏、补录、本地离线。**不做账号、不做云、不做考勤管理** |
| 本次交付 | 可运行 PWA Demo（打卡/加班/下班/月累计/补录/定位/导出），算法单测 11 项 + 端到端 24 项全部通过 |

## 1. 原始需求拆解

你描述的是一条完整闭环：

```
设置月薪 + 加班时薪 → 授权定位 + 记录公司位置 → 打卡上班
      → 实时累加今日已赚 → 下班打卡（汇总今日 + 本月）
                         ↘ 开始加班（费率切换到加班时薪）→ 下班
```

| 你提到的 | 隐含的真实需求 | 我的处理 |
| --- | --- | --- |
| 输入月薪、加班时长算时薪 | 需要一个**可解释的换算口径**，否则数字不可信 | 默认 `月薪 ÷ 21.75 天 ÷ 8 小时`，可在设置里改成真实出勤天数 |
| 加班 100/h，周末同价 | 你的合同可能是固定加班价，也可能只是估算 | 默认「固定时薪」模式；另给「按倍率」模式 + 法定下限提示 |
| 到公司才能打卡 | 防作弊 + 仪式感 | 定位围栏三档：关闭 / 提醒 / 严格，超范围可确认或拦截 |
| 实时累加 | 数字要"活着"，但别让人焦虑 | 大数字 + 500ms 节流刷新，主数字只放一个：今日已赚 |
| 下班提示今日+本月 | 需要一个**可回看的结算卡** | 底部结算弹层（不是 toast），4 个数字：今日/本月/工时/加班 |
| 月已赚 | 必须按**真实打卡记录**累计 | 只存时间段，金额每次实时推算；改月薪后历史金额同步重算 |

## 2. 三个必须定义清楚的口径（这是产品可信度的地基）

### 2.1 时薪怎么算

```
时薪 = 月薪 ÷ 月计薪天数 ÷ 每日工时
```

以你的例子：`16000 ÷ 21.75 ÷ 8 = 91.954 ≈ ¥91.95/h`，也就是 **每秒 ¥0.0255**。

| 口径 | 月计薪天数 | 时薪 | 适用 |
| --- | --- | --- | --- |
| 法定折算（默认） | 21.75 天（(365−104)/12） | ¥91.95 | 与工资条、加班费对得上 |
| 真实出勤 | 当月实际工作日，如 22 天 | ¥90.91 | 想看"我这个月实际每小时值多少" |
| 全年 250 天 | 20.83 天 | ¥96.00 | 年包折算 |

**决策：默认 21.75，设置里可改，并给一组预设：**

| 预设 | 天数 | 时薪（16000 例） |
| --- | --- | --- |
| 法定 21.75 天 | 21.75 | ¥91.95 |
| 本月工作日 | 动态计算（只排除周末） | 22 天 → ¥90.91 |
| 自定义 | 手动输入 | 按输入实时重算 |

同时在设置页把公式完整写出来——用户对"黑盒数字"零容忍。

### 2.2 加班时薪（这里有个必须提示的落差）

你给的 100 元/小时，按 91.95 的标准时薪算：

| 口径 | 加班时薪 | 相对正常时薪 |
| --- | --- | --- |
| 你的设定 | ¥100.00/h | +8.8%（每小时多 ¥8.05） |
| 工作日 1.5 倍 | ¥137.93/h | +50% |
| 休息日 2 倍 | ¥183.91/h | +100% |
| 法定节假日 3 倍 | ¥275.86/h | +200% |

节假日费率单独可设（固定时薪或倍率），因为各国/各地区规则不同；设置里维护「节假日日期列表」，命中列表的加班按节假日价计算。

**这不是挑错，是产品必须做的"提示位"**：用户很可能不知道自己的加班费低于法定参考线。Demo 里在设置页给了一条橙色提示，同时保留「固定时薪 / 按倍率」两种模式——**尊重合同事实，但把差距摊开给用户看**。计算工具不构成法律意见。

### 2.3 "本月已赚"从哪来

两种实现，差别巨大：

| 方案 | 做法 | 问题 |
| --- | --- | --- |
| ❌ 时间推算 | 按"本月已过时间 × 时薪"估 | 请假、漏打卡、调休全错；改薪后历史全乱 |
| ✅ 记录驱动 | 只存每段打卡的起止时间，金额实时算 | 数据小、可迁移、可重算 |

**决策：记录驱动。** 数据结构里金额**不入库**，永远由 `segments × 费率` 现算。副作用是"改月薪后历史金额会一起变"——这对个人工具是特性而非 bug，但要在 v1 加"按当时费率锁定历史"的开关。

### 2.4 实发校准（v0.1 已实现）

记录页按月提供「实发校准」：

- 填写当月**实际到账** → 展示 `实发 / App 估算 / 差额（正负带色）/ 反推税后时薪 / 本月总工时`。
- **不参与计时、不修改估算金额**，只做对比——避免"数字被悄悄改掉"的信任问题。
- 诚实提示：差额通常来自个税、社保、补贴、扣款或漏打卡；建议下月发薪后校准上月。
- 反推税后时薪是隐藏彩蛋：同样的 16000 税前，实发 13000 且工时 174h 时，你真正到手的时薪是 ¥74.71/h。

## 3. 状态机（Demo 已按此实现）

```
        ┌──────────── 打卡上班（定位校验） ────────────┐
        │                                            ▼
   [ 未打卡 ] ◀── 下班打卡（结算卡） ── [ 正常计时 ] ◀── 结束加班 ── [ 加班计时 ]
        ▲                                  │                     ▲
        │                                  └── 开始加班 ─────────┘
        │
   漏打卡 → 补录（手动时间段，进记录页）
   跨天 → 23:59:59 自动结算 + 提示，避免隔夜挂着计时
```

| 状态 | 主按钮 | 次按钮 | 主色 | 顶部提示 |
| --- | --- | --- | --- | --- |
| 未打卡 | 打卡上班 | — | 灰蓝 | 未打卡 |
| 正常计时 | 下班打卡 | 开始加班 | 荧光绿 | 正常工作 |
| 加班计时 | 下班打卡 | 结束加班 | 琥珀 | 加班计时中 |

**关键设计：按钮层级跟着状态走。** 用户在任何时刻只需要看"我现在最可能按哪个"，其余降级为次要按钮。

## 4. 交互与视觉决策（为什么长这样）

1. **一屏一个主角。** 首页只有一个巨大数字（今日已赚），本月金额放在次行，进度条只做背景信息。数字多了，价值感就散了。
2. **颜色即模式。** 正常=lime、加班=amber、未打卡=灰蓝。切换加班时整张卡的光晕和数字小数点颜色一起变——这是最强的即时反馈，比文字提示有效 10 倍。
3. **秒薪是情绪钩子。** `≈ 每秒 ¥0.0278` 这行小字把"熬时间"变成了"有刻度的时间"。这也是截图传播点。
4. **500ms 节流，不是逐帧。** 金额保留 2 位小数，实际每 ~2.5 秒跳一次；用 500ms 轮询保证跳变及时，又不会闪屏、耗电。
5. **结算用弹层，不用 toast。** 下班是"这一刻的高光"，给 4 个数字的回看卡；toast 只用于"已切换加班""已导出"这类轻反馈。
6. **误操作防护。** 删除记录二次确认；打卡状态全局唯一（不会出现两段同时进行中的时段）；跨天自动结算而不是无限累加。
7. **隐私即卖点。** 位置只在本地算距离、不上传；数据只在 localStorage；不要求登录。首屏没有注册墙。
8. **主题不是换皮，是场景适配。** 白天通勤/办公用「白色简洁」（默认，白底 + 墨色主按钮 + 墨绿金额）；夜间用「夜间」；偏好可爱风用「粉色可爱」（粉 + 紫的加班色）。三套共用同一套语义 token（`--money` / `--ot` / `--surface` / `--primary-bg`…），换主题只换 token，不改布局与交互逻辑；并通过 `html[data-theme]` + 首屏内联脚本做到无闪烁切换。浅色主题额外把强调色拆成 `--money`（大数字）与 `--money-ink`（小字），保证 4.5:1 可读性。

## 5. 信息架构（3 Tab，不再多）

| Tab | 内容 |
| --- | --- |
| **打卡** | 主卡（今日已赚/工时/本月/进度）、模式按钮、今日统计、今日明细、补录入口 |
| **记录** | 月切换、本月合计、按天卡片（展开看每段工时与金额）、删除、补录 |

不做"社区/晒工资"：薪资数据极敏感，社交属性会立刻劝退核心用户。分享只做**脱敏截图卡**（v2 再说）。

## 6. MVP 范围与不做清单

**做（已实现）**
- 月薪 / 计薪天数 / 每日工时 → 时薪实时换算，计薪口径支持「法定 21.75 / 不固定天数 / 自定义」
- 打卡上班、开始加班、结束加班、下班结算
- 今日/本月实时累计，月薪进度条
- 加班计费：固定时薪 / 倍率（平日、周末、节假日分别可调），带法定基准一键填入与合规提示
- 法定节假日 / 非工作日：优先读本机日历自动同步，并自动标记为休息班；失败回退服务端日历（代理 + 7 天缓存）
- 工时计算：固定工时（上下班时间自动同步每日标准工时；午休时段可设、可选是否计薪）与排班制（添加班次类型 + CSV / JSON 导入；班次设置在日历「排班」中进行）
- 日历：顶栏入口，分「收入 / 排班」标签；排班中可为日期设置班次、请假（年假/病假/事假/调休）、休息，蓝=上班、青=休息、黄=请假，原地更新不刷新
- 请假照常计薪：按每日标准工时折算日薪，计入当天与当月收入
- 打卡方式：手动 / 自动（进入公司范围静默打卡；连接指定 WiFi 弹窗确认；满足标准工时自动下班；Web 端仅定位，WiFi 读取仅 Android 壳支持）
- 账户：注册 / 登录、整包快照同步、自动同步（防抖 2.5s）、服务器地址可配
- 定位围栏（关闭/提醒/严格）+ 半径可调，默认「提醒」；已保存公司位置时不再弹窗，按已记录位置继续
- 实发校准：按月对比实发与估算、反推税后时薪
- 补录、删除、按月浏览、导出 JSON、清空
- 外观：白色简洁（默认）/ 夜间 / 粉色可爱 三套主题；支持上传自定义背景图（自动压缩、仅存本机）
- PWA：离线可用、可添加到主屏

**不做（明确延后）**
| 功能 | 为什么现在不做 |
| --- | --- |
| 账号 / 云同步 | 增加信任成本与服务器成本，验证期不需要 |
| 企业考勤 / 多人 | 完全不同的产品（B 端），会拖垮体验 |
| 个税、社保、公积金 | 规则复杂且每年变，先在 v3 做"估算"而非"精算" |
| 工资条 OCR | 识别成本高、准确率风险大，v2 之后评估 |
| 小组件 / 手表 | 需要原生外壳（Capacitor），v1 再做 |
| 社交分享 | 薪资敏感，先做脱敏卡片再考虑 |

## 7. 技术方案

| 阶段 | 方案 | 理由 |
| --- | --- | --- |
| v0（本次 Demo） | 原生 HTML/CSS/JS + localStorage + PWA，零构建 | 改一行刷新即见，验证成本最低 |
| v1 | Vite + TS（可保留原生渲染层）+ Capacitor 双端壳 | 上架、通知、小组件、后台恢复都需要原生能力 |
| 计时正确性 | **以时间戳为准，绝不用累加器** | 手机锁屏 / 后台 / 进程被杀后，累加器必然丢时间 |
| 定位 | `getCurrentPosition` 单次取点 + Haversine 距离 | 不做后台持续定位，省电且合规 |
| 存储 | JSON + `schemaVersion` 字段（v1 补） | 便于后续迁移 |
| 后端 | 零依赖 Node（`node:http` + `scrypt` + HMAC token）+ 单 JSON 快照 | 自托管成本最低，不需要数据库；后续可换 Postgres |

**同步模型**：整包快照（settings/days/months），登录时「云端 + 本机」按日期取并集（本机优先）后回传；保存后 2.5s 防抖推送。没有做多端并发冲突检测——单人多设备够用，多端并发编辑是 v1 之后的课题。

**已知限制（Demo）**
- 浏览器要求 **HTTPS 或 localhost** 才能定位；手机经局域网 HTTP 访问时定位会失败，会自动降级为手动打卡。
- 单份工作、单一时区；跨天算作"漏打卡"在 23:59 结算（真正上夜班需 v1 支持）。
- 数据只在本机，换浏览器/清缓存会丢（可导出 JSON）。

## 9. 风险与合规

1. **加班费提示 ≠ 法律意见。** 文案明确"演示数据仅作参考"，只做算术提示，不做结论。
2. **薪资隐私。** 本地优先、可导出、可清空；v1 加 Face ID / 密码锁与"一键隐藏金额"。
3. **定位权限。** 拒绝后必须能继续用（降级手动打卡并标注），否则首日流失。
4. **iOS PWA 限制。** 无后台定位、无小组件、关闭标签即停；计时逻辑已按"时间戳"设计，重新打开自动补算。
5. **应用商店。** 纯工具类可上架；若未来做"工资对账/借贷"会触碰金融合规，需提前评估。

- 启动：双击/运行 `start-demo.ps1`，或 `python -m http.server 8787 --bind 127.0.0.1`，打开 <http://127.0.0.1:8787/>
